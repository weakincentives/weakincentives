# M14 — Policy Engine Generalization

**Release:** R3. **Depends on:** R1 (egress), M12. **Dimensions:** 6, 2, 13.
**Priority:** high. **Size:** M–L.

## Objective

One declarative, composable, fail-closed, **observable** policy layer that governs
tool gating, egress, budgets, and task completion — replacing today's scattered
ad-hoc checks.

## Why (first principles)

*Policies over workflows.* The philosophy is central, but enforcement is
fragmented: tool policies (`SequentialDependency`, `ReadBeforeWrite`), the egress
allowlist (R1), budget checkpoints, and the task-completion checker are separate
mechanisms with separate shapes. Unify them: a policy is a pure decision function
evaluated at a decision point, returning allow / deny / feedback with diagnostics —
composable by conjunction, and every decision is an event.

## Scope

- **`Policy`** protocol evaluated at typed decision points: `pre_tool`,
  `egress_change`, `budget_checkpoint`, `completion`. Returns a structured
  `Decision` (allow / deny+reason / request-feedback).
- **Composition** (conjunction, ordering) and **observability** — each decision is
  dispatched as an event (visible in transcript/bundle/replay).
- **Port** the existing guardrails onto the engine: sequential-dependency,
  read-before-write, egress, budget, task-completion. Delete the bespoke paths.

## Exit criteria

- Existing guardrails reimplemented on the engine with identical behavior; every
  decision is an observable event; unmet policy fails closed.
- `make check` green.
