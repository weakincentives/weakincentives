# M8 — Unify the Tool Surface (Optional)

**Depends on:** [M7](M7.md). **Status:** optional; pursue if "every tool call is
transactional and sandbox-bound" is a hard requirement.

## Objective

Make the sandbox the target for *every* tool call by routing WINK's own
file/shell tools through `Sandbox` facets and disabling harness-native FS/shell
tools — so all tool effects pass through one `tool_transaction`.

## Why (first principles)

After M7, two tool populations still coexist: WINK-bridged tools (orchestrator
process, transactional) and harness-native tools (inside the sandbox, governed by
the harness, *not* by WINK's rollback). For full transactional totality and a
single audit path, collapse them: WINK provides the canonical read/write/edit/
grep/glob/bash tools, each a thin shim over `context.sandbox`.

## Scope

**New** — a built-in tool section exposing:

- `read`/`write`/`edit`/`glob`/`grep` over `context.filesystem`.
- `bash`/`run` over `context.shell`.

**Change — adapters**

- Disable native FS/shell tools (`disallowed_tools` / tool policies) when the
  unified surface is enabled, so the model uses the WINK tools.

## Trade-offs

| | Native tools (M7) | Unified surface (M8) |
|---|---|---|
| Transactional rollback | WINK-bridged only | **every** tool call |
| Egress under container control | file ops only | file **and** command side effects |
| Reuses harness-native ergonomics | yes | no (WINK owns the tools) |

This reverses the repo's current "harness provides file/shell tools" stance
(`WORKSPACE.md`); adopt it only where totality outweighs harness-native
ergonomics.

## Exit criteria

- With native tools disabled, a `bash` command and a file write both land in the
  sandbox and roll back together on a failed tool call.
- Toggleable per prompt/adapter; native-tool mode (M7) remains supported.
- `make check` green.
