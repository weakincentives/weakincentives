# M12 — Unify Adapter Turn-Loop + Guardrails in `_shared`

**Depends on:** none. **Unlocks:** [M13](M13.md). **Dimensions:** 5, 1.
**Priority:** high (impact). **Size:** L. **Risk:** med.

## Objective

Collapse the per-turn orchestration state machine — copied across all three
turn-based adapters — into one `_shared` implementation each adapter drives with a
single "send-one-turn" closure.

## Why

The "send prompt → collect text/usage → check completion → re-prompt (≤10 rounds)
→ visibility check" loop is reimplemented three times: `acp/_prompt_loop.py`,
`codex_app_server/_protocol.py`, `claude_agent_sdk/_sdk_execution.py`. Only the
leaf helpers (`check_task_completion`, `accumulate_usage`) are shared, so the round
cap, visibility-signal ordering, and usage accumulation can drift per adapter and
every fix needs three edits. Separately, `acp/_guardrails.py` ≡
`codex_app_server/_guardrails.py` (~110 near-identical LOC; they differ only in a
feedback `content` key and a log prefix).

## Scope

- **New `_shared/_turn_loop.py`** — `run_continuation_loop(*, send_turn, prompt, session, deadline, budget_tracker, visibility_signal, max_rounds=10)` where
  `send_turn` returns a `TurnOutcome(text, usage)`. Each adapter passes only its
  one-turn closure.
- **Move** `check_task_completion` + `append_feedback` into
  `_shared/_guardrails.py`; parameterize `append_feedback(content_type=…)`
  (`"text"` vs `"inputText"`); standardize the log events (already keyword-based).

## Exit criteria

- One continuation loop and one guardrail module; the three adapters delegate.
- ~60 LOC removed per adapter + ~110 from guardrails.
- `make check` green.
