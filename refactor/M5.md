# M5 — Dissolve `WorkspaceSection`; Unify Adapters

**Depends on:** [M4](M4.md). **Unlocks:** [M7](M7.md).

## Objective

Finish the inversion. A prompt declares a `SandboxSpec` directly; the workspace
preview becomes an auto-rendered section derived from the live sandbox; and the
adapter base owns opening/closing the sandbox and pointing the harness at
`sandbox.root`. Delete `WorkspaceSection` and every per-adapter `cwd` path.

## Why (first principles)

`WorkspaceSection` was five jobs in one class. Once intent (`SandboxSpec`),
materialization (provider), the FS facet (`Sandbox`), and rollback (M4) have
proper owners, the only thing left is rendering a file listing — which should be
derived, not authored. And every adapter resolving `cwd` differently was the
original sin behind the two-filesystem divergence; one base path fixes it.

## Scope

**Change — prompt definition**

- `PromptTemplate` accepts `sandbox: SandboxSpec | None`. (Or a tiny
  `SandboxSection` that carries only the spec + renders the preview.)
- Auto-render a "Workspace" preview section from the opened `Sandbox`
  (`filesystem.list`/mount previews) instead of from copy-time bookkeeping.

**Change — `adapters/core.py`**

- `ProviderAdapter` holds a `sandbox_provider: SandboxProvider` (default
  `LocalSandboxProvider`).
- Base `evaluate()` flow: `spec = prompt.sandbox_spec`; `sandbox = self.sandbox_provider.open(spec, …)`; thread `sandbox` into the `ToolContext`
  and set the harness `cwd = sandbox.root`; `finally: sandbox.close()`.

**Change — each adapter**

- `acp`, `codex_app_server`, `claude_agent_sdk`: delete `_resolve_cwd`, bespoke
  temp-dir handling, and workspace plumbing; read `sandbox.root`.

**Delete**

- `prompt/workspace.py::WorkspaceSection` and its refcount/clone machinery
  (materialization now lives in the provider; sharing, if needed, is a provider
  concern).

## Risks & mitigations

- *Clone/refcount semantics.* Audit who relied on `WorkspaceSection.clone`; if a
  shared sandbox across sessions is needed, model it as provider-side reuse keyed
  by `compute_workspace_fingerprint`, not section refcounts.
- *Preview fidelity.* Snapshot-test the auto-rendered preview against the old
  output for representative mounts.

## Exit criteria

- A prompt with a `SandboxSpec` runs on every adapter; `context.filesystem.root == sandbox.root ==` harness `cwd`, asserted per adapter.
- `WorkspaceSection` is gone; `grep -r WorkspaceSection src/` is empty.
- `make check` green.

> **Checkpoint:** the library now has one environment model, fully local, with the
> adapter as its factory. Everything below is additive remote capability.
