# M11 — Capability Declaration & Negotiation

**Release:** R2. **Depends on:** [M9](M9.md). **Unlocks:** [M12](M12.md).
**Dimensions:** 3, 6, 13. **Priority:** high (mission). **Size:** M.

## Objective

Reconcile what a definition **requires** with what an adapter **supports** —
satisfy, degrade gracefully, or fail closed with a precise message — so "runs on
any harness" is honest about the fact that harnesses genuinely differ.

## Why (first principles)

*Portability is contract-level, not output-level.* Harnesses are not
interchangeable: Gemini ACP reports no token usage and is HTTP/SSE-MCP only; Codex
exposes a `sandbox_mode`; the Claude SDK has bubblewrap/seatbelt isolation;
structured-output support varies. Today these leak as silent misbehavior or
per-adapter special cases. `specs/ACK.md` already defines an `AdapterCapabilities`
set for **test gating** — we make it one concept used for both runtime negotiation
*and* conformance gating (M12), so the same truth drives behavior and tests.

## Scope

- **`AdapterCapabilities`** — one declared descriptor per adapter (reconciling the
  ACK set with runtime needs): structured output, usage reporting, sandbox modes,
  skills, reasoning effort, MCP transport, cancellation, native tools.
- **Definition needs** — `requires=(…)` (hard) and `prefers=(…)` (soft) on the
  prompt/definition.
- **Negotiation** at bind/evaluate: satisfy → run; unmet *preference* → degrade
  and log; unmet *requirement* → fail closed with a typed error naming the gap,
  before any model call.
- Surface the negotiated result in telemetry; expose it to ACK (M12) so skipped
  scenarios map to declared gaps, never silent divergence.

## Exit criteria

- A definition requiring an unsupported hard capability fails closed with a precise
  message; soft preferences degrade, are logged, and are observable.
- Each adapter publishes `AdapterCapabilities`; ACK consumes the same descriptor.
- `make check` green.
