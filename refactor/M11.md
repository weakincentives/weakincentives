# M11 — Adapter Conformance Kit (Parity)

**Release:** R2. **Depends on:** [M9](M9.md), [M10](M10.md), and the `_shared`
adapter consolidation (BACKLOG hardening). **Dimensions:** 10, 13, 5.
**Priority:** high (mission). **Size:** L.

## Objective

One behavioral contract suite that **every** adapter must pass, so a single
definition behaves identically across harnesses — parity proven, not hoped for.

## Why (first principles)

*Parity is the promise.* The repo already has an `ACK` (Adapter Compatibility Kit)
spec; make it an **enforced gate**. A new adapter is "done" precisely when it
passes the kit. This is what lets users trust "define once, run anywhere," and it
turns the per-adapter duplication the review found into shared, tested behavior.

## Scope

- A shared conformance suite asserting, against each adapter (real binary or faked
  transport):
  - tool dispatch + **transactional rollback** (session + sandbox);
  - the guardrail/feedback continuation loop and completion semantics;
  - structured-output parsing;
  - transcript shape and event sequence;
  - cancellation / deadline / budget accounting;
  - sandbox parity — `filesystem`, `shell`, and egress reconfiguration;
  - error normalization to the shared exception contract.
- Wire it into CI as a required check; publish an **"adapter author checklist."**
- Build on the centralized `_shared` turn-loop/guardrails so behavior has one
  source of truth.

## Exit criteria

- The conformance suite is green for `claude_agent_sdk`, `codex_app_server`, and
  the ACP family in CI; gaps surface as explicit skips tied to `HarnessCapabilities`
  (M10), not silent divergence.
- `make check` green.
