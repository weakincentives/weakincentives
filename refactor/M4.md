# M4 — Sandbox as Execution Context

**Depends on:** [M3](M3.md). **Unlocks:** [M5](M5.md).

## Objective

Promote the environment to first-class execution context: add `sandbox` to
`ToolContext`, source `context.filesystem`/`context.shell` from it, and rewrite
transactions to snapshot **(session, sandbox)**. Remove `Filesystem`-as-a-DI
resource and the "snapshot every SINGLETON Snapshotable resource" machinery.

## Why (first principles)

The environment is as fundamental as the session and the clock — `ToolContext`
already carries those as plain fields. Threading the filesystem through the
resource registry (plus a runtime overlay to override it) was incidental
complexity that existed only because the environment had no name. With a `Sandbox`
in hand, the transaction unit becomes obvious and singular: (session, sandbox).

## Scope

**Change** — `prompt/tool.py`:

- `ToolContext` gains `sandbox: Sandbox | None`. `filesystem` becomes
  `sandbox.filesystem` (kept as a property for ergonomics); add `shell`.
- Remove the `Filesystem` resource lookup path.

**Rewrite** — `runtime/transactions.py`:

- `CompositeSnapshot` = `{ session: Snapshot, sandbox: SnapshotRef | None }`.
- `tool_transaction(session, sandbox)` snapshots both; restores both on failure.
- Delete the generic `for resource in singleton_cache if Snapshotable` loop.

**Change** — `adapters/_shared/_bridge.py`: build `ToolContext` with the
`sandbox` the adapter opened (threaded in M5); wrap execution in the new
`tool_transaction`.

**Delete** — the `Filesystem` binding in `WorkspaceSection.resources()` and any
`Prompt` runtime-resource-overlay seam (it is no longer needed).

## New shape

```python
@dataclass(slots=True, frozen=True)
class ToolContext:
    prompt: PromptProtocol[Any]
    session: SessionProtocol
    sandbox: Sandbox | None
    # …deadline, heartbeat, run_context…
    @property
    def filesystem(self) -> Filesystem | None:
        return self.sandbox.filesystem if self.sandbox else None
    @property
    def shell(self) -> Shell | None:
        return self.sandbox.shell if self.sandbox else None
```

## Risks & mitigations

- *Resource snapshot loss.* If any non-FS resource truly needs rollback, keep a
  narrow opt-in — but audit first; the filesystem was the only real user.
- *Wide blast radius.* Tools read `context.filesystem` unchanged (same facade),
  so most handlers are untouched; only construction sites and the transaction
  core move.

## Exit criteria

- A failing tool rolls back both session slices and sandbox filesystem via one
  `tool_transaction`.
- `tests/` for transactions assert (session, sandbox) snapshot/restore; the
  resource-snapshot tests are deleted with their machinery.
- `make check` green.
