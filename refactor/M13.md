# M13 — Deterministic Record & Replay

**Release:** R3. **Depends on:** [M16](M16.md). **Unlocks:**
[M15](M15.md). **Dimensions:** 10, 8. **Priority:** high. **Size:** L.

## Objective

Capture a run as a replayable trace and **replay a definition deterministically
against recorded responses** — so agents can be regression-tested, and behavior
when the definition, model, or harness changes can be **diffed** (differences are
the signal, not a parity failure).

## Why (first principles)

*Reproducible by construction.* "Test your agent" is impossible without
determinism. WINK already records transcripts, debug bundles, and session
snapshots, and injects clocks — the pieces of a replay system that don't yet
compose into one. Replay turns a recorded run into a fixture: re-run the same
definition against the *same* recorded model/harness responses and assert identical
behavior; or diff behavior when the definition, model, or harness changes — where
the diff is the expected, useful output, not a conformance claim.

## Scope

- **`ReplayTrace`** (serde artifact): the ordered prompt renders, tool
  calls + results, model outputs, usage, and negotiated capabilities (M10) of a
  run — sourced from the existing transcript/bundle.
- **Record** mode: emit a `ReplayTrace` alongside the debug bundle.
- **Replay** mode: a fake adapter/model driven by the trace + `FakeClock`, running
  the definition deterministically; assert or **diff** outputs.
- **CLI** `wink replay <trace> [--definition …] [--diff <other>]`.

## Exit criteria

- A recorded run replays to identical session state under `FakeClock`; a
  definition or model change surfaces as a structured diff.
- `make check` green.
