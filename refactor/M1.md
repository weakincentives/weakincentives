# M1 — Filesystem Narrow Waist

**Core:** Environment. **Release:** R1. **Depends on:** nothing.
**Unlocks:** [M2](M2.md), [M4](M4.md). **Size:** M–L. **Risk:** low–med.

## Objective

Replace the fat `Filesystem` protocol — reimplemented in full by every backend —
with a **narrow `FilesystemBackend`** (~10 primitives) and **one concrete
`Filesystem` facade** that composes all ergonomics (text, pagination, streaming)
once, over any backend.

## Why (first principles)

*Narrow waists; a fake in under 100 lines.* Today each backend reimplements the
whole surface: `filesystem/_host.py` (692 LOC) plus the per-backend stream stack
(`_stream_host.py` 361, `_stream_memory.py` 237, `_stream_text.py` 192,
`_stream_protocols.py` 306) plus `contrib/tools/filesystem_memory.py` (714). A
remote backend (M4) would be a third full reimplementation. With a ~10-method
backend, remote becomes cheap, fakes become trivial, and streaming/text logic has
one home. This is the load-bearing simplification of the Environment core.

## Stages (each lands green)

1. **`FilesystemBackend` protocol + `SnapshotRef`** — `root`, `read_only`,
   `stat`, `list`, `glob`, `grep`, `read_range`, `write`, `delete`, `mkdir`,
   `snapshot`, `restore`. `SnapshotRef` replaces `FilesystemSnapshot`, which today
   hard-codes git internals (`commit_ref`, `git_dir` at `_types.py:126-146`) into a
   type the in-memory backend must also pretend to satisfy — the ref becomes
   opaque, backend-private.
1. **`Filesystem` facade** — one class implementing `read`/`read_bytes`/`write`/
   `write_bytes`, `open_read`/`open_write`/`open_text`, `exists` over the backend
   primitives; keeps the existing limits (64 KB chunks, 32 MB convenience caps,
   2000-line default reads). `glob`/`grep` stay backend methods so remote backends
   run them **server-side**.
1. **Port `HostBackend`** — primitives only. Fold in the review findings: resolve
   the root once at construction (today `_resolve_path` re-resolves it on *every*
   call, `_host.py:116`); apply one `_normalize_and_validate` on **every** op
   (today `validate_path` guards writes but not reads — `_host.py:412,466,553,603`
   vs none on the read paths); decide and document the restore contract
   (`git clean -xfd` at `_git_ops.py:255` deletes *ignored* files — drop `-x`
   unless that is a deliberate, documented contract).
1. **Port `MemoryBackend`** — `contrib/tools/filesystem_memory.py` →
   `filesystem/_memory.py`, primitives only.
1. **Delete** the fat protocol and the per-backend stream modules; run the
   existing `FilesystemValidationSuite` (`tests/filesystem/`) against the facade
   over **both** backends.

## Exit criteria

- `FilesystemValidationSuite` green over `HostBackend` and `MemoryBackend`; net
  deletion ≳1,000 LOC across `filesystem/` + `contrib`.
- A toy fake backend implements the protocol in \<100 lines (test fixture).
- `make check` green.
