# M2 — Shell Facet

**Depends on:** nothing (can land in parallel with [M1](M1.md)).
**Unlocks:** [M3](M3.md).

## Objective

Give "run a command" a first-class home: a narrow `Shell` protocol and a
`LocalShell` that executes a program vector under a root directory.

## Why (first principles)

"All tool calls" includes shell. The `Filesystem` has no command surface, so a
remote sandbox could never be the target for command execution. `Shell` is the
second facet of an environment and the counterpart to `Filesystem`.

## Scope

**New** — `sandbox/_shell.py`:

- `CommandResult` frozen dataclass: `exit_code: int`, `stdout: bytes`,
  `stderr: bytes`, `truncated: bool`, `duration_s: float`.
- `Shell` protocol — `run(argv, *, cwd=".", env=None, stdin=None, timeout_s=None) -> CommandResult`. (A streaming `stream(...) -> Iterator[CommandChunk]` is
  reserved but not required here.)
- `LocalShell` — runs `subprocess.run` rooted at a directory, with output caps
  and timeout. Reuses the `git_env`-style hygiene already in `filesystem/_git_ops.py`.

`Shell` executes an `argv` vector, not a shell string — the name denotes the
surface, not `/bin/sh`.

## New shape

```python
@runtime_checkable
class Shell(Protocol):
    def run(
        self, argv: Sequence[str], *, cwd: str = ".",
        env: Mapping[str, str] | None = None,
        stdin: bytes | None = None, timeout_s: float | None = None,
    ) -> CommandResult: ...
```

## Risks & mitigations

- *Output blowups / hangs.* Cap captured bytes (mark `truncated`) and require a
  default `timeout_s`; tests assert both.
- *Determinism in tests.* Inject the clock for `duration_s`; use trivial commands
  (`echo`, `false`) so unit tests stay well under the 10 s limit.

## Exit criteria

- `LocalShell` unit tests: exit codes, stdout/stderr capture, `cwd` scoping,
  env passing, stdin, timeout, output truncation.
- `make check` green. No callers yet.
